# 文案：先判读者，再定语域

一个模块同时给三种人写字：模块界面给人、工具描述给 agent、原始输出给开发者。
读者决定写法，语域决定用词。

## 1 三类读者

| 读者 | 读什么 | 标准 |
|---|---|---|
| **agent** | 工具描述、参数说明、返回、错误、`reason` / `{blocked}`、中断通知、`context.render` | 读完知道下一次调什么 |
| **终端用户** | 模块界面、空态、阻断、按钮、配置、审批屏、agent 的交代 | 读完知道点哪 / 要不要做，且不写代码 |
| **开发者** | 日志、`detail`、原始输出 | 排障时能对照、能检索 |

审批字段归属：

| 字段 | 读者 |
|---|---|
| `needsApproval.headline` / `question` / `fallback`、`approval.plan` / `approval.render`、`approvalDetail` / `approval_note` | 终端用户 |
| `needsApproval.reason`（deny）、`{blocked}` | agent |

## 2 语域：成熟产品，不是聊天

1. **标准书面语**：不用语气词、网络语、拟人、比喻、套近乎、空话。
2. **一个概念一个词**：模块界面、工具面、技能、文档用同一个词。
3. **动词精确**：安装 / 卸载 / 更新 / 启动 / 重启 / 运行 / 停止 / 打开 / 查看 / 复制 / 重试 / 保存 / 删除 / 添加 / 移除 / 启用 / 停用 / 批准 / 允许 / 取消。版本前进一律写「更新」；必须换到更高一代才能继续时才写「升级」（dsh、工作台、适配组件的最低版本要求），且不作按钮、不作状态。
4. **状态固定**：未安装 / 已安装 / 有新版本 / 更新中 / 更新失败 / 运行中 / 进行中 / 已完成 / 待处理 / 待查看 / 等待批准 / 已暂停 / 不可用。工作台自身的启动检查状态（未就绪 / 未验证 / 版本过低）由工作台写，模块不用。
5. **句子克制**：陈述句为主；指令句用「请 + 动词」；按钮用动词原形；不用感叹号。
6. **信息完整**：发生了什么 + 原因 + 下一步。

三档语域：

| 语域 | 用在哪 | 写法 |
|---|---|---|
| 界面 | 按钮、状态、空态、阻断、错误、审批、配置 | 标准书面语；短句；固定词表；不出现内部词 |
| 交代 | agent 回复、引导 | 专业但可读；结论 + 位置 + 下一步；不寒暄、不发散 |
| 技术 | 高级设置、`detail`、日志、CLI | 术语可用，首次出现给界面词；原文原样、可检索 |

## 4 两层：界面句 + 技术细节

同一处既有用户又有技术细节时，成对写：

- **界面句**：给人，不含错误码、路径、堆栈、内部词。
- **技术细节**：给开发者，原样，放 `detail` / 折叠区 / 日志。

两条标准：

1. 只看界面句：用户知道发生了什么、下一步做什么。
2. 只看技术细节：开发能定位。

安装命令是特例：界面句说「装什么、为什么」，下一行原样命令；命令不翻译、不拆成散文。

## 5 人侧

- 空态：「还没有<对象>。」+「如何产生」。
- 阻断：「无法<动作>：<原因>。」+「下一步」。
- 错误：「<对象><动作>失败：<原因>。」+「下一步」。
- 审批：`needsApproval.headline` 写动作 + 对象（≤15 字，陈述句，不以「允许吗」收尾）；`approval.plan` 给四行（修改项 / 修改后 / 目标位置 / 影响范围；第一格可用 `objectLabel` 换领域词，可加 `extra` / `warn`）；`render` 接管详情区，返回空或抛错时退回四行。没有 headline 的旧模块才用「对象 + 动作 + 影响 + 允许吗」整句。
- 状态：「<对象><状态>」。
- 按钮：动词 + 对象。
- 配置：标签 + 一句说明 + 默认 / 影响。
- agent 交代：结论 + 位置 + 下一步。

| 位置 | 上限 |
|---|---|
| 模块标题 | ≤12 汉字 |
| 按钮 | 动词 + 对象，≤6 字 |
| 空态 | 1 句 + 可选提示 |
| 行内提示 | ≤20 字 |
| 审批标题（`headline`） | ≤15 字；英文 ≤ 中文 ×3 |
| 审批明细（`approvalDetail`，旧模块） | ≤20 字一行 |
| 审批问句（`question` / `fallback`，没有 headline 时） | ≤40 字 |

数字带单位；给人侧的时间写相对时间，给 agent 的时间戳、ID、版本原样。
状态写法见 [PANEL.md](PANEL.md) §7；审批屏见 [DESIGN.md](DESIGN.md) §3。
中文与英文都写，键带 `<unit>.`（与模块标识同名）；英文重写，不直译；中文全角标点，英文句首大写。

## 6 agent 侧

**agent 自己推得出的，不写。** 工具名、参数名、schema、上一次返回已经说了的，不重复第二遍。

- 删：字段清单、枚举释义、参数名复述、理由、输出里已有的话。
- 留：写与危险、跨工具下一步与字面量、非显然的默认与上限、会误导的坑、安全事实。
- 描述：一句「是什么」+ 一句「什么时候用」；不写「这个工具用于……」。
- 返回：事实 + 总数 / 分页 + 下一次调用；ID、版本、单位原样。
- 错误：发生了什么 + 能不能重试 + 下一步；不甩堆栈。
- 通知：自包含 —— 谁做了什么 + 哪件事变了 + 现在做什么。
- 术语与界面同名：模块、面板、看板、安装、卸载、运行中、批准。

加字先减字。模块工具的提示词没有字数闸，自己守。

## 7 开发侧

- **原文**：日志、堆栈、命令不翻译、不美化。
- **可检索**：保留错误码、路径、ID、时间戳。
- **不进界面句**：这些内容用户能看到时，折叠并标注「原始输出 / 堆栈 / 命令」；界面句不依赖它。

日志一行：目标 + 发生了什么 + 关键值原样。不写「出错了」这种没有定位信息的句子。

## 8 例

下表用虚构的发布模块举例，只演示写法，不指工作台内置功能。

| 场景 | 现在 | 改成 |
|---|---|---|
| 空态 | 暂无数据 | 这个环境还没有构建记录。换一个环境，或先运行一次构建。 |
| 阻断 | 系统内部错误，请稍后重试 | 本次未读取到发布记录。请检查网络后重试。 |
| 按钮 | 确定 | 发布到生产 |
| 描述 | 用于查看构建状态的工具 | 查看某个环境最近一次构建：状态、耗时、提交；用户说「发布没成功」时先调用。 |
| 返回 | 操作成功 | 已发布 v1.2.3 到生产；下一步查看构建结果。 |
| 拒绝 | 不允许 | 这个环境是生产环境；请先在确认条上选择「发布到生产」。 |
| 日志 | 出错了 | `[inventory] release v1.2.3 failed: HTTP 502 (retryable)` |

## 9 验

1. 卡片：`dsh-wb-module check --only cards` 覆盖的八种工作台侧输入各看一遍，两语各一遍；抓 `undefined` / `NaN` / 裸键。
2. 审批：跑 `dsh-wb-module check`，`contracts` 会验 `headline` 15 字、`question` / `fallback` 40 字、`approvalDetail` 20 字与 `plan` 四行；再在真审批屏上走一遍。
3. 两条标准都过：只看界面句能行动，只看技术细节能定位。
4. 工具：注册后读描述，逐句问「模型推得出来吗」；真调一次读返回；漏参数读报错。
5. 拿五个用户会说的话试：只凭描述能不能挑中这把工具。
6. 过四问：名词在界面上找得到吗？动词是标准词吗？状态是固定词吗？下一步清楚吗？
