# 常见问题

## 启动失败

| 症状 | 怎么办 |
| --- | --- |
| 启动被拒，提示 dsh 太旧 | 升级 Desktop，再重启；仍被拒时先在模块市场更新工作台 |
| 启动正常但页面没有反应 | 重启 Desktop；仍有问题请检查插件开关与终端输出 |

## 浏览器连接

| 症状 | 怎么办 |
| --- | --- |
| 「准备工作台」里「连接浏览器 · 还没连上」 | 通常是扩展未安装或未启用。请从 [Chrome 应用商店安装 OpenCLI](https://chromewebstore.google.com/detail/opencli/ildkmabpimmkaediidaifkhjpohdnifk)，在扩展页确认已启用，保持浏览器打开，再回到这一屏选择「重试」 |
| 选择「打开浏览器」没有反应 | 这个按钮只在 Desktop 里出现；它会打开上次承载扩展的那个浏览器（没记住就用 Chrome）。如果打开后仍然连不上，请检查扩展是否被禁用 |
| 提示连接了多个浏览器账号 | 每个浏览器账号各有一个扩展实例，工作台不会自行猜测。请按页面上给出的命令列出账号，并选择一个默认账号 |
| 面板一直空白 / 持续加载 | 请依次确认：这个工作区已安装模块、要查看的平台已登录、「准备工作台」里「连接浏览器」那一行显示已连接；第一次加载可能需要几秒 |

## 界面不对

| 症状 | 怎么办 |
| --- | --- |
| 左栏恢复出厂、右侧面板消失 | 插件被关闭了。打开 Settings → 插件，重新启用 `@dsh-workbench/core`；如果进不去，按 `Meta+,` |
| 左栏没有「工作台 DIY」、模式里也没有「工作台 DIY 模式」 | 通常是 dsh 版本太旧：DIY 模式在启动时从本次 dsh 的 `standard` 派生，旧版本没有注册入口就无法派生，而且不会报错。「准备工作台」会指出这一点并给出升级命令，升级后重启即可 |
| 打开面板 / 按刷新要等 5–8 秒 | 正常现象：opencli 每次调用都有固定开销，数据一律实时读取、不使用缓存 |
| 页面白屏 / 提示插件加载失败 | 通常是插件冲突。请重启 Desktop 并检查插件开关；仍未解决就到仓库提交 issue |

## 数据对不上

- 会话、项目、附件放在 `~/.dsh` 下，安装或卸载工作台都不会修改它们。
- 设置与插件沿用 Desktop 的那份配置；工作台不另存一份。
